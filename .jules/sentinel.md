## 2024-05-24 - Unsafe Environment Manipulation in Test Runner
**Vulnerability:** Data races/flaky tests caused by multithreaded modification of `std::env` state using `unsafe { std::env::set_var() }` and `remove_var()` within individual `#[tokio::test]` functions.
**Learning:** Rust's standard test runner executes tests concurrently. Mutating global process state like environment variables inside tests without synchronization or isolation leads to unpredictable behavior, spurious test failures, and potential memory unsafety (which is why `set_var` is unsafe in Rust).
**Prevention:** Avoid mutating global state in tests. When tests strictly require specific environment variables or CWD changes to be validated, encapsulate the test logic into an isolated subprocess (e.g., using `std::process::Command::new(std::env::current_exe().unwrap())` guarded by an internal env var flag like `RUN_TEST_XYZ`).

## 2024-05-24 - TOCTOU and Silent I/O Error Swallowing in File Operations
**Vulnerability:** TOCTOU risks leading to unintended file overwrites and destruction of existing permissions when trying to append data (like `.secrets`).
**Learning:** Using `tokio::fs::read_to_string(path).await.unwrap_or_default()` gracefully falls back to an empty string on *all* errors, not just when a file doesn't exist. If the file exists but isn't readable due to `PermissionDenied`, it swallows the error, returns an empty string, and the subsequent append logic overwrites the existing file data completely with only the new changes.
**Prevention:** Instead of `.unwrap_or_default()`, use an explicit `match` statement on the `Result`. Default to an empty string *only* if `e.kind() == std::io::ErrorKind::NotFound`. Properly bubble up or handle all other genuine I/O errors (`Err(e) => return Err(e.into())`) to prevent data loss or silent failures.
